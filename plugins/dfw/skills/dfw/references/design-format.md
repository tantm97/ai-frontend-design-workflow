# Design workspace format (framework-neutral)

```
PRODUCT.md                 product context (dfw template; read by Impeccable/Hallmark)
DESIGN.md                  design system document (dfw-owned)
design/
  design.json              manifest: screens, variants, states, themes, breakpoints, components, flows
  tokens/tokens.json       W3C DTCG 2025.10 tokens (source of truth for values)
  tokens/themes/<name>.json  optional overrides -> [data-theme="<name>"]
  tokens/tokens.css        generated by `dfw tokens build` (never edit)
  styles/*.css             shared CSS (base.css + component styles), tokens only
  components/<name>.html   reusable component sheets with all states
  screens/<screen>/<variant>.html
  assets/                  user-supplied brand assets (unaltered) and placeholders
  approved/vN/             frozen snapshots (immutable) + approval.lock.json
  handoff/vN.md            design-to-implementation contract
```

## design.json
```json
{
  "schema": 1,
  "product": "Stockroom",
  "surface": "product",
  "breakpoints": [{ "id": "desktop", "label": "Desktop", "width": 1440, "height": 900 }],
  "themes": ["dark"],
  "states": ["empty", "loading", "error"],
  "flows": [{ "id": "receive", "title": "Receive stock", "screens": ["inventory-list", "receive-form"] }],
  "components": [{ "id": "data-table", "file": "components/data-table.html" }],
  "screens": [
    {
      "id": "inventory-list",
      "title": "Inventory list",
      "flow": "Inventory",
      "route": "/inventory",
      "description": "Find items, see stock health, start receiving.",
      "approvedVariant": "b",
      "variants": [
        { "id": "a", "label": "A - Dense table", "file": "screens/inventory-list/a.html", "mode": "layout" },
        { "id": "b", "label": "B - Table + health rail", "file": "screens/inventory-list/b.html", "mode": "layout", "recommended": true }
      ]
    }
  ]
}
```
Schema: `schemas/design-manifest.schema.json` in the dfw plugin.

## Rules for HTML screens
- Plain HTML + CSS; small inline JS only for demonstrating interaction (tabs, menus); no frameworks, no CDN scripts, no build.
- Load `../../tokens/tokens.css` and shared styles with relative paths so files also open directly.
- All colors, spacing, radii, fonts, shadows, durations via `var(--token)`; the lint flags hard-coded colors.
- `data-dfw-id` on every meaningful element: lowercase, dot-separated, unique per file, stable across edits (`area.element`, e.g. `filter-bar.search`). Shared components keep a prefix (`data-table.header`). Never rename ids casually; comments reference them.
- Semantic HTML first (landmarks, headings in order, labels, buttons vs links); this carries to implementation.
- Realistic content and edge cases (long names, zero/huge numbers, empty lists, errors, permissions).
- States: `html[data-state="empty"] .rows { display: none }` style switches; themes via tokens.
- Images: user assets or neutral placeholders with honest alt text; never hotlinked stock images.

## Tokens (DTCG 2025.10)
- Colors: `{"$type":"color","$value":{"colorSpace":"srgb","components":[r,g,b],"hex":"#rrggbb"}}` or `oklch` components.
- Dimensions: `{"$type":"dimension","$value":{"value":16,"unit":"px"}}`. Durations `{value, unit:"ms"}`.
- Aliases: `"$value": "{color.brand.600}"`. Group `$type` is inherited.
- Name semantically for roles (`color.surface`, `color.ink`, `color.accent`, `color.danger`), keep raw scales separate (`color.blue.600`).
