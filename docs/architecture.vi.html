dfw: để Claude thiết kế giao diện trước, rồi mới code

dfw là một plugin cài vào công cụ AI viết code (hiện có Claude Code và GitHub Copilot). Khi bạn nhờ Claude làm giao diện, dfw bắt Claude đi theo đúng trình tự của một đội thiết kế chuyên nghiệp: hiểu sản phẩm → đưa ra thiết kế cho bạn xem và góp ý → bạn duyệt → mới viết code → kiểm tra code có giống thiết kế không.

Tài liệu nội bộCài vào Claude CodeXem thiết kế trên trình duyệtBạn duyệt từng bước

Tóm tắt trong 30 giây

  • Bạn mô tả sản phẩm bằng lời, xem thiết kế trên trình duyệt, bấm vào chỗ muốn sửa để góp ý, và nói "duyệt" khi đã ưng.
  • Claude hỏi cho rõ yêu cầu, đề xuất phong cách, dựng bộ màu/chữ/nút dùng chung, dựng từng màn hình, sửa theo góp ý, rồi code thật.
  • dfw giữ trật tự: Claude không được code trước khi bạn duyệt, thiết kế tự được kiểm tra lỗi sau mỗi lần sửa, và mọi quyết định đều được lưu lại thành file.

Đọc trang này thế nào

  • Mới làm quen: đọc mục 1–6, rồi 19–21.
  • Muốn hiểu code và kiến trúc: mục 7–17.
  • Muốn sửa hoặc cải thiện dfw: mục 22 (bảng tra "muốn đổi gì thì sửa file nào") và 24.
  • Chạy trên nhiều công cụ AI (Claude Code, Copilot; sau này OpenCode, Codex, Cursor): mục 18.

Bắt đầu1. dfw dùng để làm gì

Khi nhờ AI làm giao diện mà không có quy trình, thường gặp những vấn đề dưới đây. dfw sinh ra để giải quyết đúng các vấn đề đó.

Không có dfwCó dfw

Bắt đầu2. Một dự án chạy thế nào

Toàn bộ quá trình gồm 7 bước. Ô xanh dương là việc của bạn, ô tím là việc của Claude, ô xanh lá là code thật. Hình thoi đỏ là lúc Claude dừng lại chờ bạn duyệt.

Từng bước, bạn sẽ thấy gì

  1. Tìm hiểuClaude hỏi vài câu về người dùng, mục tiêu, dữ liệu, thiết bị. Kết quả là file PRODUCT.md mô tả sản phẩm. Bạn chỉ cần trả lời trong chat.
  2. Chọn phong cách (G1)Claude đưa 2–3 hướng thiết kế khác nhau, ví dụ "gọn gàng kiểu công cụ chuyên nghiệp" hay "mềm mại, thân thiện". Bạn chọn một, hoặc kết hợp.
  3. Bộ nền design system (DS)Trước khi vẽ màn nào, Claude dựng bộ dùng chung: bảng màu, cỡ chữ, khoảng cách, và các component như nút, ô nhập, bảng, thẻ. Bạn xem tất cả trên một trang và duyệt.
  4. Màn hình và góp ý (G2)Claude dựng từng màn bằng cách ghép các component ở bước 3, nên mọi màn đồng bộ. Bạn mở Studio (một trang web chạy trên máy bạn, giống Figma), bấm vào chỗ muốn sửa và ghi góp ý. Claude sửa xong thì báo lại. Khi ưng, bạn duyệt và thiết kế được chụp lại thành phiên bản cố định (v1), không ai sửa được nữa.
  5. Chọn công nghệ (G3)Claude xem project đang có gì (hoặc đề xuất mới) và đưa ra framework, thư viện. Bạn duyệt.
  6. CodeBây giờ Claude mới được viết code thật, dựa trên tài liệu handoff sinh ra từ thiết kế. Trước G2 và G3, dfw tự chặn mọi lần Claude định ghi code.
  7. Kiểm tra (G4)Claude chạy app, chụp màn hình ở nhiều kích thước và so với thiết kế. Bạn xem danh sách chỗ lệch và quyết định chấp nhận hay sửa.
Trong suốt quá trình, sau mỗi lần Claude sửa thiết kế, dfw tự kiểm tra lỗi (màu sai, chữ đè nhau, bị tràn…) và bắt Claude sửa trước khi đưa cho bạn xem. Bạn không phải làm gì thêm.

Business flow5. Ví dụ một dự án từ đầu tới cuối
